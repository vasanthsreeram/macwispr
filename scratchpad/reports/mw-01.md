## Root cause (measured)

Gatekeeper checks the DMG itself when the user opens it. `scripts/build-dmg.sh` only ran `dmgbuild` and copied the result. It never called `codesign`, `notarytool`, or `stapler` (measured: I read the script at `1f8d428`). The app signing in `sign-and-notarize.sh` covers only `MacWispr.app`.

## What changed

| File | Change |
|------|--------|
| `scripts/build-dmg.sh` | When `MACWISPR_SIGN_IDENTITY` is set, it runs `codesign --timestamp` on the DMG and `codesign --verify --strict`. It then requires `stapler validate` to pass on the app, runs `notarytool submit --wait --output-format json`, and requires status `Accepted` (otherwise it prints `notarytool log` and exits 1). Finally it staples the DMG and runs `stapler validate` and `spctl -a -vvv -t open --context context:primary-signature`. It copies the stable-name DMG only after stapling. It uses the same credential variables as `sign-and-notarize.sh` and honors `MACWISPR_SKIP_NOTARIZE=1`. With no identity, it skips signing and prints "do not publish this DMG". |
| `scripts/release.sh` | If the app is signed with Developer ID, it refuses to publish when either DMG fails `stapler validate`. |
| `.github/workflows/release.yml` | New "Install dmgbuild" step (venv, sets `MACWISPR_PYTHON`). The job never had `dmgbuild` (inferred; it never got this far). The existing "Build, sign, and notarize" step now does the DMG signing, notarization, and stapling through `./scripts/build-dmg.sh`, then runs `stapler validate` and `spctl` on both DMGs. |
| `docs/context/SIGNING.md` | Adds DMG verification commands and the "Re-ship only the DMG" steps. |

## How to re-ship the v1.2.10 DMG

Run this on Vasanth's Mac, which has the Developer ID cert and `.env.signing`, from a checkout of this branch (or of main after merge):

```bash
source .env.signing            # MACWISPR_SIGN_IDENTITY + MACWISPR_NOTARY_PROFILE
V=1.2.10
OUT="$(mktemp -d)"
gh release download "v$V" -p "MacWispr-$V-macos-arm64.zip" -D "$OUT"
ditto -x -k "$OUT/MacWispr-$V-macos-arm64.zip" "$OUT"
xcrun stapler validate "$OUT/MacWispr.app"
MACWISPR_VERSION=$V DIST_DIR="$OUT" ./scripts/build-dmg.sh "$OUT/MacWispr.app"
gh release upload "v$V" "$OUT/MacWispr-$V-macos-arm64.dmg" "$OUT/MacWispr-macos-arm64.dmg" --clobber
```

`dmgbuild` must be importable. If it isn't, run `python3 -m venv /tmp/dmgvenv && /tmp/dmgvenv/bin/pip install dmgbuild && export MACWISPR_PYTHON=/tmp/dmgvenv/bin/python3`.

What it changes for users:

- New downloads open without the "cannot be verified" warning.
- The app inside is byte-identical to the released 1.2.10 app (it comes from the release zip).
- The zip, Sparkle appcast, version number, and release notes stay the same. Existing installs are not affected.
- It replaces only the two DMG assets.

Do **not** use `workflow_dispatch` with `tag=v1.2.10` for this:

- The repo has no signing secrets, so it fails at validation.
- It checks out the old tag's scripts, so it would build an unsigned DMG anyway.
- It would rebuild the zip and rewrite the appcast.

Do **not** use `scripts/release.sh v1.2.10` either. It overwrites the release notes with stale 1.2.3 text.
